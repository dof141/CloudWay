# 浏览器端运行配置设计

## 目标

将 CloudWay 的第三方服务密钥和小红书 Cookie 保存到用户自己的浏览器中。后端可以使用这些配置完成旅行规划、地图查询、图片查询和 AI 对话，但不得将配置写入 `.env`、数据库、任务历史文件或日志。

本次按项目当前约束实现单用户最小版本，不处理多个用户同时提交不同密钥时的隔离问题。

## 方案选择

采用浏览器 `localStorage` 持久化配置，并由 Axios 请求拦截器在需要访问后端的请求中附带配置。后端读取配置后仅覆盖当前进程内存中的运行配置，不再写入 `runtime_settings.json`。

未选择的方案：

- `sessionStorage`：安全性稍高，但关闭标签页后需要重新填写，不符合持久保存要求。
- 完整请求级依赖注入：能够支持多用户并发隔离，但需要改造 LLM、地图、Agent 等全局单例，超出本次最小实现范围。

## 浏览器端

现有导航栏设置弹窗保持不变，保存操作改为只写入 `localStorage`，不再调用 `PUT /api/settings`。打开弹窗时直接读取浏览器配置，不再从后端读取密钥。

设置表单顶部显示固定提示：“配置仅保存在当前浏览器中，服务器不会保存。”该文案需要提供中文、英文和日文翻译。

保存的字段包括：

- 后端 API 地址
- 高德 Web 服务 Key
- 高德 JavaScript Key
- Google Maps API Key 与代理
- 小红书 Cookie
- LLM API Key、Base URL 和模型名称

设置弹窗增加“清除配置”操作，删除上述浏览器数据并恢复部署时提供的非敏感默认值。

Axios 请求拦截器从 `localStorage` 读取后端所需配置，通过专用请求头发送。密钥不得出现在 URL、查询参数或前端控制台日志中。高德 JavaScript Key 和 Google Maps Key 继续由前端地图组件直接读取。

## 后端

后端增加统一的客户端运行配置读取逻辑，负责：

1. 从专用请求头读取配置。
2. 对空值和长度进行基础校验。
3. 将有效字段应用到当前进程的运行配置。
4. 配置变化时重置 LLM、地图服务和旅行规划 Agent 单例，使新配置立即生效。
5. 未携带某项配置时回退到服务器环境变量，兼容现有部署方式。

`GET /api/settings` 和 `PUT /api/settings` 不再返回或持久化密钥。可以保留路由用于兼容旧前端，但只返回配置状态或应用临时配置。

## 数据流

1. 用户在设置弹窗填写配置并保存到当前域名的 `localStorage`。
2. 用户提交旅行规划，前端在请求头中携带后端所需配置。
3. 后端在创建后台任务前应用内存配置并重置相关单例。
4. `TripRequest` 只包含旅行参数，任务状态持久化时不会接触密钥。
5. 图片、聊天、地图等后续 HTTP 请求同样通过拦截器携带配置。
6. 服务重启后后端内存配置消失，浏览器仍保留用户配置，下次请求会重新发送。

## 安全约束

- 线上必须使用 HTTPS，避免传输过程中泄露配置。
- 后端不得输出请求头或密钥值。
- 错误响应只说明缺少或失效的配置，不回显原值。
- `.env` 继续作为部署方可选的回退配置，但用户填写的值不得写入该文件。
- `localStorage` 可被同源脚本读取，因此不得引入不可信前端脚本，并提供清除配置入口。

## 错误处理

- 缺少 LLM Key：在开始规划前返回明确提示。
- 缺少高德 Web Key：地图相关功能按现有降级逻辑处理。
- 小红书 Cookie 无效：保持现有认证失败提示，引导用户在设置中更新。
- 浏览器存储不可用：设置保存失败并提示用户检查隐私模式或浏览器权限。

## 验收标准

- 保存设置后刷新页面，配置仍可从当前浏览器读取。
- 设置弹窗明确提示配置仅保存在当前浏览器中，服务器不会保存。
- 后端不再生成或更新 `runtime_settings.json`。
- `backend/data/trip_tasks/*.json` 中不包含 API Key、Cookie 或完整运行配置。
- 修改浏览器配置后，新提交的任务使用新配置。
- 清除配置后浏览器中不再保留密钥。
- Docker 部署可以不在服务器 `.env` 中填写用户级密钥，由用户在页面设置中提供。
